# rbs-core

The shared runtime of projects generated by [rbs](https://github.com/tky0065/rbs), a web API
framework for Rust built on Axum and SeaORM.

This crate carries what has no reason to differ from one API to the next. Everything a
developer will want to read or change is generated into their own source tree by the `rbs`
command, not hidden here.

## You do not usually add this by hand

`rbs new` writes `rbs-core` into the manifest of the project it generates, with the database
feature you picked. Reaching for `cargo add rbs-core` in an unrelated project is possible, but
the crate is designed as the runtime half of a generated project — start with
[`rbs-cli`](https://crates.io/crates/rbs-cli) and the
[getting started guide](https://tky0065.github.io/rbs/getting-started).

## What it gives you

- **Errors.** One `Error` type for the whole chain — repository, service, controller — and a
  `Result<T>` alias. Every variant renders as an RFC 9457 `application/problem+json` response;
  database and internal failures keep their source for the log and never leak it to the client.
- **Configuration.** Five layers merged in order — defaults, `config/default.toml`,
  `config/{RBS_ENV}.toml`, `.env`, environment — and validated at boot.
- **Logs.** Two formatters, chosen by `RBS_LOG_FORMAT`: one readable in development, one JSON
  for production.
- **State.** `CoreState` holds the connection pool and the configuration, and `HasCoreState`
  lets the runtime's own handlers reach it through whatever `AppState` your project wraps it in.
- **Request plumbing.** `ValidatedJson` extractor, `Pagination`/`Page`, a correlation id per
  request, an HTTP trace layer, and a `/health` route.
- **OpenAPI.** `ProblemDetails` and `CommonResponses` declare the error responses once, for
  every utoipa path in the project.

## Feature flags

`postgres` (default), `mysql` and `sqlite` select the SeaORM driver — pick exactly one.

`auth` adds Argon2 password hashing, JWT signing and verification, opaque tokens, and an
`Identity` extractor.

`redis`, `mail` and `storage` are declared but **empty**: they reserve the names for planned
extensions and activate nothing today.

## What it deliberately leaves out

Your `AppState`, your router, your entities, your features. Those are generated into your
project, as plain Rust with no macro to unfold, and no rbs release rewrites them.

## Stability

Inside the 1.x line the public API of this crate is frozen: nothing is removed, renamed or
given another meaning, and `cargo-semver-checks` fails the build rather than let it happen. The
[compatibility page](https://tky0065.github.io/rbs/compatibility) sets out the scopes.
