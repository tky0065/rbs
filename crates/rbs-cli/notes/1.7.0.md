# rbs 1.7.0

## Deux fragments posent un frontend, et rien ne change sans vous

`rbs add frontend` installe une application Vue 3 dans votre projet ; `rbs add
frontend-admin` y ajoute un shell d'administration authentifié. Aucun projet existant ne
bouge tant que vous n'installez ni l'un ni l'autre, et `cargo build` continue de réussir
sur une machine sans Node — le mécanisme des fragments reste déclaratif, si bien que le CLI
ne lance jamais `npm`.

## L'ancre des exclusions manque à tout projet antérieur

`# <rbs:ignore>`, dans `.gitignore`, est neuve : c'est par elle qu'un fragment exclut du
dépôt ce qu'il y dépose — les dépendances et le build du client, pour celui-ci. Votre
`.gitignore` ne la porte pas, et la règle habituelle s'applique : ancre absente, le CLI
n'écrit rien dans le fichier et affiche le bloc à coller. `rbs doctor --fix` la repose sous
la ligne d'accroche qu'elle déclare ; le lancer avant `rbs add frontend` évite de découvrir
le collage au milieu de l'installation.

Les deux autres ancres neuves — `// <rbs:admin_routes>` et `// <rbs:admin_rail>` — vivent
dans des fichiers que seul `frontend-admin` dépose. Elles ne vous concernent donc pas avant
d'avoir installé ce fragment, et `rbs doctor` les tient pour inapplicables tant qu'il n'est
pas là. Le registre passe de dix-huit à vingt ancres, dont neuf optionnelles.

## `rbs generate crud` écrit désormais des écrans, sur un projet qui porte le shell

Sur un projet portant `frontend-admin`, la commande émet aussi l'écran d'administration de
la table — liste filtrée, formulaire, détail — et le monte par les deux ancres ci-dessus.
Aucun drapeau ne le demande : la commande lit les fragments installés et adapte sa sortie,
comme elle écrit des routes fermées depuis la 1.3 dès qu'`auth` est posé. `--no-admin` est
la sortie de secours, pour une table que personne ne doit administrer depuis l'interface.

Sans le fragment, la commande se comporte exactement comme avant, sans un mot de plus.

L'écran appelle le client typé, que la commande ne régénère pas — elle compile le projet, ce
qu'une génération n'a jamais fait. Elle affiche donc la ligne à relancer : sans elle, la
vérification des types de votre frontend s'arrête sur un import que rien n'a écrit.

## `rbs generate client --lang ts` corrige un client que TypeScript refusait

Tout composant du document OpenAPI qui n'est pas un objet — une énumération, et toute
entité portant un champ `enum` en déclare une — était rendu en `export interface X <union>`,
qui n'est pas du TypeScript : le fichier entier cessait de s'analyser. Ces composants se
déclarent désormais en alias de type.

Si vous régénérez un client sur un projet qui n'en souffrait pas, une seule chose peut
bouger : le corps d'un composant objet *nullable* passe d'une déclaration multi-ligne à un
alias sur une ligne. Le type décrit est le même.
