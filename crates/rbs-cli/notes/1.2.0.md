# rbs 1.2.0

## `GET /health` contrôle les dépendances installées

Le contrôle de santé ne pingait que la base : un projet dont le cache Redis était mort
répondait `ok`, et l'orchestrateur gardait le pod en rotation. Les fragments `redis` et
`storage` inscrivent désormais leur sonde, et le corps porte une clé par dépendance :

```json
{ "status": "unavailable", "checks": { "database": "ok", "cache": "unreachable" } }
```

Les sondes sont menées de front et bornées séparément à deux secondes : ajouter une
dépendance n'allonge pas la réponse. Une seule injoignable suffit à faire un `503`.

`mail` et `jobs` n'ont pas de sonde. La file de `jobs` est une table de la base, déjà
contrôlée ; ouvrir une connexion SMTP à chaque appel de `/health` — plusieurs fois par
minute sous un orchestrateur — coûterait cher et ferait passer le service pour un client
abusif auprès du relais, alors qu'un transport momentanément muet n'empêche pas l'API de
répondre.

## Une douzième ancre, et ce qu'un projet antérieur doit faire

`// <rbs:health_probes>` vit dans `src/health/controller.rs`, et c'est là que les fragments
inscrivent leur sonde. **Un projet créé avant la 1.2.0 ne l'a pas**, et `rbs doctor` la
réclame :

```
✗ ancres     health_probes manque dans src/health/controller.rs
```

`rbs doctor --fix` ne la reposera pas tout seul, et le dira :

```
! health_probes n'a pas été reposée — la ligne d'accroche `vec![` est introuvable dans src/health/controller.rs
```

Le message est juste : l'ancre vit *dans* la liste des sondes, et l'ancien contrôleur
n'en a pas. Remplacez son corps par celui-ci, une fois :

```rust
pub async fn health(State(state): State<AppState>) -> Response {
    rbs_core::health::report(
        state.core().db(),
        vec![
            // <rbs:health_probes>
            // </rbs:health_probes>
        ],
    )
    .await
}
```

`use rbs_core::HasCoreState;` est à ajouter en tête si le fichier ne l'a pas. `doctor`
repasse au vert, et le prochain `rbs add redis` inscrira sa sonde tout seul.

Un projet qui ne veut pas des sondes n'a rien à faire : `rbs_core::health::handler` existe
toujours et se comporte comme avant.

## `rbs doctor --fix` repose les ancres absentes

Une ancre supprimée par mégarde se réparait par un copier-coller ; elle se répare par une
commande. Chaque ancre déclare la ligne après laquelle elle vit, et `--fix` s'abstient en
le disant plutôt que de viser à côté — une ancre reposée au mauvais endroit coûte plus
cher qu'une ancre absente : `<rbs:layers>` glissée sous `request_id` cesserait de voir
l'identifiant de la requête, et rien ne le dirait avant la lecture d'un journal.

`--force` accompagne `--fix` pour écrire malgré un working tree Git sale. Seul, il est
refusé : rien d'autre n'écrit.

## `rbs completions <bash|zsh|fish|powershell|elvish>`

```bash
rbs completions zsh > ~/.zfunc/_rbs
```

Les sous-commandes, les drapeaux et les noms de fragments se complètent à la tabulation.
Le catalogue ne descend pas dans le parseur : `rbs add ma-feature --template-dir ./mes-templates`
installe toujours un fragment dont aucun binaire ne porte le nom.

## `rbs add observability`

Traces OpenTelemetry et métriques Prometheus. L'export ne part que si vous nommez un
collecteur — `OTEL_EXPORTER_OTLP_ENDPOINT`, et `OTEL_SERVICE_NAME` pour le nom du service ;
sans elles, la feature installée reste inerte et `cargo run` démarre comme avant.

`/metrics` n'est **pas** monté sur le routeur public : un second listener le sert sur
`observability.metrics_port`, 9090 par défaut. Les métriques publient la topologie interne
du service, et l'exposer sur le port de l'API demanderait une règle de reverse-proxy à
chaque déploiement — qu'un déploiement finit par oublier.

Les séries portent le **gabarit** de route et non l'URL demandée : `/articles/{id}` fait
une série, pas une par article.

Appelez `rbs_core::logs::shutdown()` avant de rendre la main dans `main` : sans cet appel,
un arrêt brutal perd le dernier lot de spans.

## `rbs-core` : `Health` et `Checks` ne dérivent plus `Copy`

Le nombre de sondes varie d'un projet à l'autre, et les accueillir demande une allocation.
Aucune fonction publique de la crate ne rend ni ne prend ces types — `handler` et `report`
rendent une `Response` — et tous deux sont `#[non_exhaustive]` : hors de la crate,
personne ne peut détenir la valeur dont la copie disparaît. Rien à changer.
