## 2. r/rust

Titre :

```
rbs 1.9.0 — an Axum + SeaORM scaffolder whose generated code is yours from the moment it is written
```

Corps :

```
rbs generates a web API into your own `src/`: entity, DTO, filter, repository, service and
controller, plus its SeaORM migration, from a single `--fields` list and with no database
running. What it generates is ordinary code you are meant to read and edit; the CLI never
rewrites a syntax tree, it only inserts between comment anchors, and a generated project
builds, tests and runs on a machine that does not have rbs installed.

What sits in the runtime crate (`rbs-core`) is only what has no reason to differ from one
API to the next: the error type and its RFC 9457 body, configuration, logging, the pool,
OpenAPI helpers. Everything else is generated.

1.9.0 is about proof rather than features:

- Every command output the documentation or the READMEs show is now replayed by a test and
  compared character by character to what the command actually prints — or the page says why
  it cannot be. Several were lying: `rbs add auth` writes 51 files, not 40.
- A project carrying every feature is now compiled on macOS and Windows in CI. Nothing
  generated had ever been built outside Linux, and the first symptom was a mojibake dash in
  `make help`.
- An agent scenario, run by hand, checks that a coding agent starting from a fresh project
  can add a feature through the CLI, with `rbs doctor` staying green.

There is also a page comparing rbs and Loco on philosophy rather than feature lists, with
every claim about Loco dated and sourced.

Install: `cargo install rbs-cli` (the name `rbs` was taken). Docs and a recording of the
whole flow are in the README.

Feedback welcome, especially from anyone who has run a generator and then wanted to change
what it produced.
```
