# Double licence — plan d'implémentation

**Goal:** Que les deux crates portent `MIT OR Apache-2.0` et que `cargo publish --dry-run`
ne signale aucun problème de licence.

**Architecture:** La spec §6.3 tranche : double licence, convention de l'écosystème Rust,
valable pour les crates publiées comme pour le code généré — un projet issu de `rbs new`
appartient à son auteur, sans licence héritée. Le champ va dans `[workspace.package]`, que
les deux crates héritent déjà pour `version`, `edition`, `rust-version` et `repository`.

**Spec:** `docs/superpowers/specs/2026-08-25-rbs-design.md` §6.3.

## Global Constraints

- Branche dédiée `f8-licence`.
- Textes de licence **intégraux et non modifiés**, aux seuls champs de copyright près.
- `rbs-cli` dépend de `rbs-core` par `path` : `cargo publish --dry-run` échouera sur cette
  dépendance non publiée tant que `rbs-core` n'est pas sur crates.io. Le critère porte sur
  la licence : si un autre motif d'échec subsiste, il est consigné tel quel, sans être
  maquillé en succès.

## File Structure

- Create: `LICENSE-MIT`, `LICENSE-APACHE`
- Modify: `Cargo.toml` — `license` dans `[workspace.package]`
- Modify: `crates/rbs-core/Cargo.toml`, `crates/rbs-cli/Cargo.toml` — `license.workspace`
