**Interfaces:**
- Produces: `metadata::project_root(start: &Path) -> Result<PathBuf, RootError>` où
  `RootError` distingue `Absent` (aucun manifeste rbs jusqu'à la racine) de
  `Illisible(metadata::Error)`.
- Produces: `doctor::base::database_of(root: &Path) -> Result<Database, metadata::Error>`.

**Contrat de remontée — à respecter au mot près.** `metadata::read` rend
`Error::PasUnProjet` quand le manifeste est lisible mais ne porte pas
`[package.metadata.rbs]`. C'est le cas de la crate `migration`, et c'est ce qui fait
fonctionner le doc-commentaire actuel de `project_root`. Donc :

| Résultat de `read` sur le `Cargo.toml` d'un ancêtre | Comportement |
|---|---|
| `Ok(_)` | racine trouvée, on s'arrête |
| `Err(PasUnProjet)` | **on continue** de remonter |
| `Err(Syntaxe \| Acces \| Field \| MoteurInconnu \| Declaration \| …)` | **on s'arrête** et on remonte la faute avec son chemin |
| plus aucun ancêtre | `RootError::Absent` |

Un `Err(Acces)` dont la cause est `io::ErrorKind::NotFound` signifie « pas de `Cargo.toml`
ici » et doit faire **continuer** la remontée, comme `PasUnProjet`.

```rust
/// MySQL refuse un index sur une colonne TEXT sans longueur de préfixe (erreur 1170),
/// et la faute ne se verrait qu'au `rbs migrate up`, longtemps après la commande.
#[test]
fn unique_on_a_text_field_is_rejected() {
    let error = parse("bio:text:unique").expect_err("`unique` sur `text` est refusé");

    assert_eq!(error.errors.len(), 1);
    assert_eq!(error.errors[0].label, "bio");
    assert_eq!(
        error.errors[0].kind,
        ErrorKind::IndexOnText {
            modifier: "unique".to_string()
        }
    );
}

/// `index` tombe sous la même contrainte que `unique`.
#[test]
fn index_on_a_text_field_is_rejected() {
    let error = parse("bio:text:index").expect_err("`index` sur `text` est refusé");

    assert_eq!(
        error.errors[0].kind,
        ErrorKind::IndexOnText {
            modifier: "index".to_string()
        }
    );
}
```
