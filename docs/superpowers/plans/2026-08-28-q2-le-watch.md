# `rbs dev` — le watch

**But :** un fichier de `src/` sauvegardé relance le serveur, et le serveur précédent
libère réellement son port.

**Approche :** `watchexec 8.4` en dépendance de `rbs-cli`, comme la conception du jalon le
tranche. Le filtrage est une fonction pure — `restarts(chemin)` — et non un réglage enfoui
dans le moteur : c'est la seule forme qui se teste sans toucher au disque ni attendre un
événement.

Le point dur est la coupure. `watchexec::command::SpawnOptions { grouped: true }` pose
`ProcessGroup::leader()` sous Unix et un **Job Object** sous Windows ; `Job::stop()` tue
alors le groupe entier, et non le seul `cargo run`. Sans lui, le binaire compilé — petit-fils
du CLI — survit et garde le port.

La preuve doit tourner dans les trois jobs de la CI, donc sans Docker, sans base et sans
projet généré. Le test se suffit : il relance **son propre exécutable de test** dans deux
rôles, par variable d'environnement. Le rôle `parent` lance un `enfant` et attend ; le rôle
`enfant` écoute sur `127.0.0.1:0`, écrit le port obtenu dans un fichier et attend. Le test
supervise le `parent` par un `Job` construit avec les options de production, l'arrête, puis
vérifie que plus rien ne répond sur le port de l'enfant.

Les deux rôles portent une échéance de survie : une preuve qui échoue ne doit pas laisser
un processus derrière elle.

**Écarté :** un script shell comme processus d'essai — `cmd.exe` n'a pas de quoi ouvrir un
port. Un binaire d'essai dédié — il partirait dans le paquet publié.

**Hors périmètre :** le debounce, laissé au défaut de watchexec.

## Fichiers

| Chemin | Rôle |
|---|---|
| `crates/rbs-cli/src/dev/watch.rs` | `restarts()`, `command()`, `run()` |
| `crates/rbs-cli/src/dev/mod.rs` | l'étape `Serveur` passe la main au watch |
| `crates/rbs-cli/Cargo.toml` | `watchexec`, ses deux crates de types, `tokio` |

`watchexec-events` et `watchexec-signals` entrent avec `watchexec`, aux versions qu'il
épingle : `Filterer::check_event` se signe avec `Event` et `Priority`, et l'arrêt propre
nomme `Signal::Terminate`. Ce sont ses propres crates, non une dépendance de plus.

## Étapes

- [ ] `restarts()` : `target/`, `.git/` et le reste du bruit exclus ; `src/**.rs` retenu.
- [ ] `command()` : `SpawnOptions { grouped: true }`, `cargo run` dans la racine.
- [ ] `run()` : `Watchexec`, `pathset` sur la racine, filtre, `Signal::Interrupt` → quit.
- [ ] Test de coupure : deux rôles, un port, `Job::stop()`, port libre.

## Preuves attendues

- ✓ *Fichier de `src/` touché → redémarrage ; `target/` → rien* — test unitaire sur
  `restarts()`.
- ✓ *Le serveur enfant meurt avec son groupe* — test de coupure, sur les trois
  plateformes de la CI.
