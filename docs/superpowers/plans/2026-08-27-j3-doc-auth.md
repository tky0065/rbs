## La contrainte qui fixe le design

`integration_examples.rs:53` n'autorise que trois fichiers retouchés à la main dans
`blog-auth` : `posts/controller.rs`, `posts/tests.rs`, `auth/guard.rs`. Tout le reste est
comparé octet à octet à une génération fraîche. **Aucune région nouvelle ne sera posée** :
la page se sert des neuf existantes, et cite `.env.example` et `config/default.toml`
entiers — le plugin accepte `file=` sans `region=`.

## Plan de la page

| Section | Extrait |
|---|---|
| Ce qu'installe `rbs add auth` | sortie de commande, bloc `bash` |
| Le secret, et pourquoi le projet ne démarre pas | `.env.example`, `config/default.toml` |
| Le cycle des jetons — rotation, révocation | prose |
| Protéger une route | `region=create`, `region=require_role` |
| Les rôles — la promotion passe par la base | `region=jeton_admin` |
| Tester une route protégée | `region=signee`, `region=refus` |

Fait saillant que la page doit dire : `examples/blog-auth/.env` ne porte pas
`RBS_AUTH__SECRET`, `add auth` ne l'écrivant que dans `.env.example`. L'exemple, tel que
le CLI le produit, ne démarre pas — friction que `doctor` diagnostique depuis J4.

## `--with` : ce qui est corrigé, ce qui ne l'est pas

`valider_features` rejette **toute** feature, connue ou non. Le message des connues dit
« que cette version n'expose pas encore » : `add docker`, `add ci` et `add auth` existent
tous, il est faux.

Corrigé : `auth` entre dans `FEATURES_CONNUES`, et le message renvoie vers `rbs add`
sans prétendre que la commande manque.

Non corrigé : `--with` continue de ne rien installer. Faire poser les features à la
création est un changement de comportement, non une correction de documentation.
