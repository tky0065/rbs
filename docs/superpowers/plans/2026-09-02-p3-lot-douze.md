# Douze tâches P3 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fermer les douze tâches ouvertes d'`IMPROVE.md` — 123, 109, 99, 85, 92, 93, 94, 100, 102, 103, 118, 121.

**Architecture:** cinq groupes indépendants, un worktree par groupe. `G1` (docs) et `G2`
(exemple) touchent `docs/` et `examples/` ; `G3` ne touche que `crates/rbs-core` ; `G4`
trois points isolés de `crates/rbs-cli` ; `G5` l'outillage de test partagé.

**Tech Stack:** Rust 2024, Axum, SeaORM, minijinja (délimiteurs alternatifs), utoipa,
`assert_cmd` + `testcontainers` pour les tests lents, Docusaurus pour `docs/`.

**Spec:** `docs/superpowers/specs/2026-09-02-doc-transcripts-design.md` (groupes G1 et G2
seulement ; les autres groupes sont des correctifs bornés dont la preuve est dans
`IMPROVE.md`).

## Global Constraints

- **Commits** : Conventional Commits, sujet en français à l'impératif, sans majuscule ni
  point final. **Aucun** identifiant de tâche, **aucun** renvoi à `IMPROVE.md`,
  `TODO.md`, un lot ou un plan. **Jamais** de `Co-Authored-By` ni de mention d'un
  assistant. Corps : le pourquoi technique, puis un intertitre `Vérifications :` avec les
  commandes lancées et leur résultat réel.
- **Commentaires** : le *pourquoi*, jamais le *quoi*. `#![warn(missing_docs)]` sur
  `rbs-core` : tout item public porte un `///` d'une à trois lignes.
- **Documentation bilingue** : toute page modifiée en anglais l'est aussi en français,
  dans le même commit.
- **Bloquant avant de cocher** : `cargo fmt --all --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo test --workspace`.
- **Tests lents** : tout ce qui compile un projet engendré ou demande Docker porte
  `#[ignore = "…"]` avec sa raison.
- **`examples/`** : toute template modifiée fait échouer `integration_examples` tant que
  les exemples n'ont pas suivi ; les régénérer **par diff entre deux générations**, jamais
  par écrasement (`examples/README.md` donne les commandes exactes).
- **Un problème croisé en route se corrige dans le même lot** — rien ne repart au backlog.

- Produces: `pub trait Ping { fn ping(&self) -> impl Future<Output = Result<(), DbErr>> + Send; }`,

- [ ] **Step 1: Écrire le test qui échoue**

```rust
/// Une base joignable mais muette est le cas que `DatabaseConnection` ne sait pas
/// représenter : son pool répond tout de suite, connecté ou non.
struct BaseMuette;

impl Ping for BaseMuette {
    async fn ping(&self) -> Result<(), DbErr> {
        std::future::pending().await
    }
}

#[tokio::test(start_paused = true)]
async fn a_database_that_never_answers_gives_a_503_over_http() {
    let app = Router::new().route(
        "/health",
        axum::routing::get(|| async { report(&BaseMuette, Vec::new()).await }),
    );

    let response = app
        .oneshot(
            Request::builder()
                .uri("/health")
                .body(Body::empty())
                .expect("requête valide"),
        )
        .await
        .expect("le router doit répondre");

    assert_eq!(response.status(), StatusCode::SERVICE_UNAVAILABLE);

    let bytes = to_bytes(response.into_body(), usize::MAX)
        .await
        .expect("corps lisible");
    let body: Value = serde_json::from_slice(&bytes).expect("corps JSON");
    assert_eq!(
        body,
        json!({ "status": "unavailable", "checks": { "database": "unreachable" } })
    );
}
```
