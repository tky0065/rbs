# Génération des DTO — plan

**But :** produire `features/<nom>/dto.rs` — `Create<Entite>`, `Update<Entite>`,
`<Entite>Response` — depuis le même `Feature` que D2.

**Approche :** template `templates/feature/dto.rs.jinja` et `generate/dto.rs`. `Create`
porte les champs déclarés, `Update` les mêmes tous en `Option`, `Response` y ajoute `id` et
les deux timestamps plus un `From<Model>`.

**Validation :** `#[validate(email)]` est posé d'après le *nom* du champ — `email` ou
suffixe `_email` — et seulement sur `string` et `text`. La grammaire de D1 est close : y
ajouter un type `email` rouvrirait une tâche prouvée.

## Étapes

- [ ] Étendre la sérialisation de `Champ` (ou la vue de `Feature`) d'un `valide_email`.
- [ ] `templates/feature/dto.rs.jinja` : trois structs, `Deserialize + Validate + ToSchema`
      sur les deux entrantes, `Serialize + ToSchema` sur la sortante.
- [ ] `generate/dto.rs` : `rendre(&Feature)`. Tests : présence des trois structs, `Update`
      entièrement optionnel, `Response` porte `id`/`created_at`/`updated_at`.

## Preuve attendue
