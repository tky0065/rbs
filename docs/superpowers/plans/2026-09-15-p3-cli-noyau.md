# Lot P3 CLI, noyau et dépendances — plan d'implémentation

> **Pour l'agent qui exécute :** suivre ce plan tâche par tâche avec
> `superpowers:executing-plans`, en TDD (`superpowers:test-driven-development`) : voir le
> test échouer avant d'écrire le code. Les étapes se cochent (`- [ ]`) au fil de l'eau.

**But :** mettre le lock à jour et retirer l'exception d'audit périmée, retirer trois
features vides de `rbs-core`, factoriser la lecture de l'UUID de l'appelant, donner des
options à `rbs dev`/`rbs test`, franciser l'aide et les erreurs d'usage de clap.

**Architecture :** cinq tâches séquentielles sur une seule branche. L'ordre compte : le
lock d'abord (tout le reste compile dessus), la francisation en dernier (elle réécrit
toutes les transcriptions d'aide de `docs/cli/`, que la tâche 4 modifie aussi).

**Stack :** Rust 2024, clap 4.6 (derive), minijinja (délimiteurs `{@ @}`), Docusaurus.

**Spec :** design validé en conversation le 2026-09-15 ; tâches 67, 66, 62, 60 et 58
d'`IMPROVE.md` (lire leur ligne : elle porte le `fichier:ligne` du diagnostic).

## Contraintes globales

- **Branche :** `git checkout -b improve/p3-cli-noyau improve/p3-lot`. Avant la première
  ligne : `git rev-list --count HEAD..improve/p3-lot` doit rendre `0`, sinon
  `git merge improve/p3-lot` d'abord.
- **Commits :** Conventional Commits, sujet français à l'impératif, sans majuscule ni
  point final. Corps : le *pourquoi*, puis `Vérifications :` avec les commandes lancées
  et leur résultat réel. **Jamais** d'identifiant de tâche (`#62`…), de renvoi à
  `IMPROVE.md`/`TODO.md`/un plan, ni de ligne `Co-Authored-By` ou `Claude-Session`.
- **Ne pas toucher `IMPROVE.md`** : l'orchestrateur coche.
- **Documentation bilingue :** toute page `docs/docs/…` modifiée l'est aussi sous
  `docs/i18n/fr/docusaurus-plugin-content-docs/current/…`, dans le même commit.
  `CHANGELOG.md` et `CHANGELOG.fr.md` : section `[1.5.0]`, même nombre d'items.
- **Exemples :** toute template modifiée rend `integration_examples` rouge tant
  qu'`examples/` n'a pas suivi. Régénérer **par diff entre deux générations**
  (`examples/README.md` donne les commandes exactes), jamais par écrasement : les
  exemples portent des éditions à la main. `patch --no-backup-if-mismatch`, sinon un
  `.orig` fait échouer `integration_examples`.
- **Code d'un fragment :** `cargo check --manifest-path examples/<ex>/Cargo.toml
  --all-targets` avant toute passe Docker — le code des templates n'est compilé nulle
  part ailleurs.
- **Passes lentes (Docker) :** une commande par suite, `--no-fail-fast` **avant** le `--`,
  sortie redirigée vers
  `/private/tmp/claude-501/-Users-yacoubakone-dev-rs/b9dae65b-ac43-40c1-833d-4c73520587e2/scratchpad/lotA-<suite>.log`
  (préfixe `lotA-` obligatoire : un autre agent écrit dans le même répertoire). Le shell
  coupe à 600 s : lancer en arrière-plan.
- **Littéraux :** avant de changer un message engendré, `grep -rn '<message>'
  crates/rbs-cli/tests` — les tests lents figent des chaînes de fragments.
- **Shell zsh :** `ls` est `eza` (`command ls`), guillemets autour des motifs `*`,
  jamais `===` nu. Le binaire se lance par `cargo run -q -p rbs-cli --bin rbs -- …`
  (`which rbs` rend le rbs de Ruby).
- **Portes finales de chaque tâche :** `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Hors périmètre rencontré en route → le noter dans le rapport final, ne pas le corriger.
