# Commande `rbs new` complète — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** assembler les briques C2 → C6 en une commande qui crée un projet démarrable : rendu des templates, écriture de l'arborescence, `.env` portant l'URL choisie, `git init`.

**Architecture:** un module `new` qui suit la séquence du §4.4 — planifier, vérifier, appliquer. Tout le rendu se fait en mémoire avant la première écriture : une variable manquante ou un répertoire occupé doivent échouer sans avoir rien créé. L'écriture qui échoue en cours de route retire le répertoire qu'elle a créé, jamais un répertoire préexistant. Trois décisions structurent le module :

- **`rbs_core_dep`.** Le noyau n'est pas publié : le projet généré porterait une dépendance introuvable. Le défaut reste la version du CLI — ce que verra l'utilisateur d'une installation depuis crates.io — et `--core-path` écrit `{ path = … }`. C'est aussi ce dont C8 et D13 auront besoin pour compiler le projet généré en CI.
- **`.env` séparé de `.env.example`.** L'exemple est versionné par le projet et doit rester générique ; l'URL réellement choisie va dans un `.env` que le squelette gitignore. Une template dédiée porte la variable, plutôt qu'une substitution de ligne dans le code du CLI.
- **Features refusées avant écriture.** `docker` et `ci` s'installent par le mécanisme `add` (lot E), absent. Les demander fait sortir en erreur avant toute création : `metadata.rbs` ne doit jamais déclarer une feature que rien n'a posée, sous peine de rendre son installation ultérieure impossible — l'idempotence du §4.2 porte sur ces métadonnées.

**Tech Stack:** minijinja, include_dir, inquire, toml_edit, `std::process::Command` pour `git init`.

**Spec:** `docs/superpowers/specs/2026-08-25-rbs-design.md` §4.1, §4.2, §4.4

## Global Constraints

- Aucune écriture avant que les vérifications et le rendu complet aient abouti.
- Un échec après la création du répertoire le retire ; un répertoire préexistant n'est jamais touché.
- `git init` en échec avertit sans faire échouer la commande : le projet est valide sans dépôt.
- Les tests de ce lot ne compilent pas le projet généré — c'est C8. Ils portent sur les fichiers écrits.
- `cargo clippy --workspace --all-targets -- -D warnings` et `cargo fmt --all --check` restent propres.
