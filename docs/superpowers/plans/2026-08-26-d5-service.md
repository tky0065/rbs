# Génération du service — plan

**But :** produire `features/<nom>/service.rs` — les mêmes cinq opérations que le
repository, mais en DTO d'entrée et de sortie, et les décisions métier avec.

**Approche :** template `templates/feature/service.rs.jinja` et `generate/service.rs`.

```rust
pub async fn list(db, pagination: &Pagination)     -> Result<Page<<Entite>Response>>
pub async fn find(db, id)                          -> Result<<Entite>Response>
pub async fn create(db, entree: Create<Entite>)    -> Result<<Entite>Response>
pub async fn update(db, id, entree: Update<Entite>)-> Result<<Entite>Response>
pub async fn delete(db, id)                        -> Result<()>
```

**Frontière :** n'importe que `super::dto` et `super::repository` — `ActiveModel` arrive
par la réexportation posée en D4. Aucun `EntityTrait`, aucune requête : `DatabaseConnection`
n'est que transmis.

**Décisions portées ici :** l'absence devient `Error::NotFound("<singulier>")` dans `find`,
`update` et `delete` ; `list` assemble le `Page<T>` de `rbs-core` ; `update` charge, écrit
les seuls champs `Some` et pose `updated_at` — visible et modifiable, là où l'utilisateur
le cherchera, plutôt que dans un trigger ou un `ActiveModelBehavior`.
