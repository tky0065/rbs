# `AppState` — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** donner au runtime un accès au pool et à la configuration sans lui faire posséder l'état applicatif, qui appartient au projet généré.

**Architecture:** la spec §3.2 range `state.rs` du côté généré : `rbs-core` ne peut donc pas porter la struct `AppState`. Il porte à la place `CoreState` — le couple pool + configuration, clonable à coût nul — et le trait `HasCoreState` par lequel ses propres handlers l'atteignent. Le `state.rs` du projet composera `CoreState` dans son `AppState` et y ajoutera ce qu'il veut. Les champs de `CoreState` restent privés : un projet qui lirait `state.core.db` transformerait tout ajout de champ dans le noyau en rupture.

**Tech Stack:** `axum` (`State`, `FromRef`), `sea-orm`, `tower` (dev, pour `ServiceExt::oneshot`).

**Spec:** `docs/superpowers/specs/2026-08-25-rbs-design.md` §3.2, §3.4

## Global Constraints

Dans `state.rs`, un `AppState` de test composant `CoreState` comme le fera le projet généré :

```rust
#[derive(Clone)]
struct AppState {
    core: CoreState,
    salutation: &'static str,
}

impl HasCoreState for AppState {
    fn core(&self) -> &CoreState {
        &self.core
    }
}

#[tokio::test]
async fn un_handler_extrait_l_etat_du_projet_et_repond() {
    async fn handler(State(state): State<AppState>) -> String {
        format!("{} {}", state.salutation, state.core().config().env)
    }

    let app = Router::new()
        .route("/", get(handler))
        .with_state(etat("bonjour"));

    let reponse = app
        .oneshot(Request::builder().uri("/").body(Body::empty()).unwrap())
        .await
        .unwrap();

    assert_eq!(reponse.status(), StatusCode::OK);
    let corps = to_bytes(reponse.into_body(), usize::MAX).await.unwrap();
    assert_eq!(&corps[..], b"bonjour development");
}

#[test]
fn l_etat_se_clone_sans_copier_la_configuration() {
    let etat = etat("bonjour");
    let clone = etat.clone();

    assert!(Arc::ptr_eq(&etat.core.config, &clone.core.config));
}

#[test]
fn core_state_sert_d_etat_a_lui_seul() {
    let core = etat("bonjour").core;

    assert_eq!(core.core().config().env, core.config().env);
}
```

- [ ] **Step 4 : implémenter `state.rs`**

- `pub struct CoreState { db: DatabaseConnection, config: Arc<Config> }`, `#[derive(Clone, Debug)]`. Champs privés : commenter le *pourquoi* (upgradabilité du noyau).
- `new(db, config)` prend la `Config` par valeur et enveloppe elle-même dans l'`Arc` — l'appelant n'a pas à connaître ce détail.
- `db()` et `config()` renvoient des références empruntées.
- `pub trait HasCoreState: Clone + Send + Sync + 'static { fn core(&self) -> &CoreState; }`. Les bornes sont celles qu'Axum exige d'un état ; les porter sur le trait évite de les répéter sur chaque handler du noyau.
- `impl HasCoreState for CoreState` : un routeur sans état applicatif propre peut servir les handlers du noyau, ce dont `/health` (B8) se sert.
